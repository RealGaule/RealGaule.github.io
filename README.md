# Project website

One [Hugo](https://gohugo.io/) site with the
[PaperMod](https://github.com/adityatelange/hugo-PaperMod) theme, built from the repository root:

- `/`: notes (home page lists them; each note is at `/posts/<slug>/`), plus
  `/archives/`, `/search/`, `/tags/`, `/cheatsheet/` (writing cheatsheet) and `/projects/`.
- `/mtod/`: **Sample, Then Refine: Training-Free Diffusion for Offline Global Trajectory Planning**,
  a hand-written HTML/CSS page. Hugo copies `mtod/` verbatim (a static mount in `hugo.toml`),
  so it is not themed and needs no build step of its own.
- The old `/notes/...` URLs redirect to the new pages.

The project page displays its title, a short English Motivation, one continuous
BRHP schematic, an illustrative single-denoise particle animation, and three
saved-trajectory GIFs labeled only by task name.
Required template/license credits remain at the bottom. There are no project-author
names, affiliations, JavaScript, or analytics.
This does not anonymize the GitHub repository or its commit history.

`live/` is a separate, local-only tool (the Claude Live viewer, see `live/README.md`).
It is never part of the published site.

## Local preview

Hugo **extended 0.166.0**. The theme is a git submodule pinned to commit
`d3768854d00a` (`themes/PaperMod`); after cloning, fetch it with:

```sh
git submodule update --init
```

Preview with live reload, from the repository root:

```sh
/home/tianyuliu/website/.tools/hugo server
```

Open <http://localhost:1313/> (the project page is <http://localhost:1313/mtod/>).
The production build (what CI runs) is `hugo --gc --minify`, which writes `public/`.

Layout:

- `hugo.toml`: site settings, menu (笔记 · 项目 · 归档 · 搜索 · 标签 · 写作速查), home intro,
  and the `mtod/` mount.
- `content/posts/<slug>/index.md`: one note per page bundle; its images sit next to it.
- `content/cheatsheet/`: the writing cheatsheet with every syntax example.
- `content/projects.md`: the project list; `content/archives.md`, `content/search.md`.
- `static/`: favicons (drawn from `static/favicon.svg`).
- `layouts/`, `assets/css/extended/`, `i18n/`: overrides of the theme
  (post title block, byline, left-margin table of contents, boxes, figures, KaTeX).
  Colours, fonts and the text column are CSS variables in `assets/css/extended/00-theme.css`.

## Writing notes

**New note.** Either copy an existing bundle folder, or run
`/home/tianyuliu/website/.tools/hugo new content posts/<slug>/index.md`
(uses `archetypes/posts.md`; it starts as `draft: true`, which `hugo server -D` shows).
Front matter: `title`, `date`, a one-line `description` (the subtitle), `tags`,
and optionally `summary` (card text) and `lastmod` (shown as 更新 in the byline).
Do not repeat the title as a `#` heading; sections start at `##`. The table of
contents lists `##` and `###`.

**Math** (KaTeX, every page): inline `$...$` or `\(...\)`, display `$$...$$` or
`\[...\]`. A literal dollar sign is `\$`. In a table cell write `\|` or `\vert`
instead of a bare `|`.

**Boxes**: theorem, definition, conclusion, formula, note, tip. Prefix every line
with `> ` and leave a blank line between two boxes:

```markdown
> [!theorem] 定理 1（标题，可含 $x$）
> 正文、列表、表格都可以。
> $$
> F(U) = -\lambda \log Z(U).
> $$

> [!tip]- 点击展开的提示（`-` 折叠，`+` 默认展开）
> ...
```

Without a title the box is labelled 定理 / 定义 / 结论 / 公式 / 注 / 提示.

**Figures** are numbered automatically (图 1, 图 2, …); write the caption without
a number:

```markdown
{{< figure src="plot.svg" alt="…" caption=`说明文字，可含 $x_t$ 与 **加粗**` >}}
```

`src` is a file in the same bundle (or `/path` under `static/`). The
image links to itself, so a click opens it full size (`link="…"` sets another
target, `link="none"` turns it off).
Footnotes use `text[^1]` and `[^1]: …`. A reference list is a numbered list
right after a heading whose text ends in `文献` (for example `## 7. 文献`).
See `content/cheatsheet/index.md` for every example.

The figure `content/posts/gibbs-convolution/gibbs-convolution.svg` is
generated by `tools/render_gibbs_convolution.py` (needs NumPy and Matplotlib,
e.g. `/usr/bin/python3 tools/render_gibbs_convolution.py`).

## The `/mtod/` project page

The diagram is editable vector artwork at `mtod/static/images/brhp-overview.svg`.
The figure is one left-to-right tree with a central selected lineage, omitted
intermediate expansion, and schematic objective landscapes at the first and final
layers. Its short labels are in English; click it to open the full-size SVG.

The particle animation illustrates the proposed **single-denoise** MToD variant
on a one-dimensional analytic mixture, not a robot task or benchmark result.
The same particles first sample stochastically and then undergo deterministic,
annealed mean-shift refinement along one continuously decreasing noise schedule.
There is no particle restart or second noise schedule at the phase boundary.
The right panel distinguishes the empirical particle density from the smoothed
target density; mode-seeking refinement need not preserve the target distribution.
This illustration does not change the optimizer: the current benchmark MToD
implementation still uses its two-process sample/refine design.
The layout is inspired by the density-evolution illustrations on the
[Temporal Score Rescaling project page](https://temporalscorerescaling.github.io/);
the simulation and rendered assets here are original, not copied from that site.
Recreate it with `python tools/render_mtod_density.py` after installing NumPy,
Matplotlib, and Pillow. The generator and its JSON manifest record the toy target,
seed, noise schedule, switch point, and particle updates.

The GIFs replay saved MPPI-BRHP consistency-test trajectories for Double Cart-Pole,
Walker, and Push T; they are not new optimization runs or claims of task success.
They are stored in `mtod/static/gifs/`; clicking a GIF opens its full-size version.

## GitHub Pages and domains

Pages deploys through GitHub Actions (`.github/workflows/deploy.yml`): on each
push to **main**, it checks out the repository with its submodule, downloads
Hugo extended 0.166.0 (checksum-verified), runs `hugo --gc --minify`, and publishes
`public/`. Only Hugo's output is published, so `live/`, `tools/` and this README are not.
In **Settings → Pages**, **Source** must be **GitHub Actions**.

A custom domain can be added later through Pages settings and the domain's DNS
configuration. The project path remains `/mtod/`; relative asset links do not
need changing. No custom domain or `CNAME` file is preset here.

The earlier template repository is retained as a reference and does not need a
separate Pages deployment.
